# generated-signature

Sign generated files so hand edits are detected, while keeping manual sections editable.

[![npm package](https://badge.fury.io/js/generated-signature.svg)](https://www.npmjs.com/package/generated-signature)
[![License](https://img.shields.io/npm/l/generated-signature.svg)](https://github.com/JacobLey/leyman/blob/main/tools/generated-signature/ts/LICENSE)

</div>

Generated files often start with a "do not edit" comment, but nothing enforces it. A hand edit goes unnoticed until the next regeneration overwrites it.

`generated-signature` signs a generated file with a hash of its content, written into the file as a comment. `verify()` needs only the file (not the generator) to tell whether someone edited it, so it is cheap enough to run in a lint rule or a pre-commit hook. The package also ships an ESLint rule, `generated-signature/eslint`, that reports hand-edited files in the editor.

Parts of a file can be left as manual sections for people to edit. Their content is left out of the signature, and carried over when the file is regenerated. The markers take up whole lines, so verifying a file doesn't need to know its comment syntax, and helpers render the markers in the comments of common file types. Files that can't hold comments, like JSON, are recorded in a [manifest](#manifest) instead.

It has no dependencies besides `node:crypto`. `eslint` is an optional peer, needed only for the ESLint entry point. A [Go implementation](https://github.com/JacobLey/leyman/tree/main/tools/generated-signature/go) signs and verifies files the same way.

A valid signature only means nobody edited the file. It doesn't mean that regenerating it would produce the same output, so it isn't a check that the file is up to date.

Guides and the full reference are on the [docs site](https://jacobley.github.io/leyman/packages/generated-signature/).

## Install

```sh
npm i generated-signature
```

## Example

```ts
import { manualSection, mergeSections, sign, verify } from 'generated-signature';

const generated = `export class AutoGenerated {
${manualSection({ id: 'value', body: 'static readonly VALUE = 123;', indent: '    ', filePath: 'foo.ts' })}

    add(input: number): number {
        return input + AutoGenerated.VALUE;
    }
}
`;

// First write: insert a signature line.
let text = sign(generated, { filePath: 'foo.ts' });

verify(text); // { status: 'valid' }
verify(text.replace('123', '456')); // { status: 'valid' }, inside a manual section
verify(text.replace('input +', 'input -')); // { status: 'invalid' }

// Regenerating: keep what people wrote in manual sections.
const existing = text.replace('123', '456');
const { text: merged, orphans } = mergeSections({ generated, existing });
text = sign(merged, { filePath: 'foo.ts' }); // VALUE is still 456
```

## Usage

`generated-signature` is an ESM module. It must be `import`ed. To load from a CJS module, use dynamic import: `const { verify } = await import('generated-signature');`.

A generator renders its output (with `manualSection()` for editable regions), merges in the existing file's sections with `mergeSections()`, and signs the result with `sign()`. Anything can then call `verify()` on the file to find out whether someone edited it outside the manual sections.

[`populate-files`](https://www.npmjs.com/package/populate-files) is the intended writer, but the package works on plain strings and has no opinion on how files are written.

### File format

```ts
// @generated-signature v1:3f9a0c… Generated file. Do not edit outside of manual sections.
export class AutoGenerated {
    // @manual-start value
    static readonly VALUE = 123;
    // @manual-end value
}
```

- The signature token is `@generated-signature v1:` followed by 32 lowercase hex characters. It must appear exactly once, anywhere in the file. `sign()` inserts it as the first line (after a shebang, an XML declaration, or Markdown front matter) unless the text already has one, so a generator with its own header can place it there with [`signatureToken()`](#signaturetoken).
- A manual section starts at a line containing `@manual-start <id>` and ends at a later line containing `@manual-end <id>`. Ids are letters, digits, `_`, `.` and `-`, unique per file. Sections do not nest. The marker must be at the start of the line or after whitespace.
- The hash is SHA-256 (first 128 bits) of the file with `\r\n` normalized to `\n`, the token's hash replaced by zeros, and every section body removed. The marker lines are hashed, so adding, removing or renaming a section is detected. `v1` versions this algorithm.

## API

### `sign(text, options?)`

Fills in the signature token's hash, inserting a signature line first if the text has none.

| Parameter | Type     | Description                                        |
| --------- | -------- | -------------------------------------------------- |
| `text`    | `string` | Required. Generated file content.                  |
| `options` | `object` | Required only when `text` has no token. See below. |

| Option                 | Type                      | Default                                                     | Description                                                                                                                                        |
| ---------------------- | ------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filePath` / `comment` | `string` / `CommentStyle` | —                                                           | Required. Comment syntax for the inserted line, either looked up from a file name (see [`commentStyle`](#commentstylefilepath)) or given directly. |
| `message`              | `string`                  | `'Generated file. Do not edit outside of manual sections.'` | Text after the token on the inserted line.                                                                                                         |

**Returns** `string`: the signed text. Signing is idempotent, and preserves `\r\n` line breaks.

**Throws** `GeneratedSignatureMalformedError` for a duplicate or unsupported token, or malformed sections. `GeneratedSignatureCommentStyleError` when a line must be inserted and `filePath` has no known comment syntax. `TypeError` when a line must be inserted and no options are given.

---

### `signatureToken()`

**Returns** `string`: a token with a placeholder hash. Generators with their own header put it there, and `sign()` fills in the hash instead of inserting a line:

```ts
sign(`// AUTO-BARREL ${signatureToken()}\nexport * from './foo.js';\n`);
```

---

### `verify(text)`

Checks the file's signature.

**Returns** `VerifyResult`, discriminated on `status`:

| `status`      | Meaning                                                                         |
| ------------- | ------------------------------------------------------------------------------- |
| `'valid'`     | Signed, and unchanged outside manual sections.                                  |
| `'invalid'`   | Signed, but changed outside manual sections.                                    |
| `'unsigned'`  | No signature token.                                                             |
| `'malformed'` | Has an `error: GeneratedSignatureMalformedError` explaining what can't be read. |

Never throws for any input string.

---

### `manualSection(options)`

Renders a manual section for a generator to embed.

| Property               | Type     | Default | Description                                                                |
| ---------------------- | -------- | ------- | -------------------------------------------------------------------------- |
| `id`                   | `string` | —       | Required. Section id.                                                      |
| `body`                 | `string` | `''`    | Default content, until someone edits it. A trailing line break is ignored. |
| `indent`               | `string` | `''`    | Prefixed to both markers and every non-blank body line.                    |
| `filePath` / `comment` |          | —       | Required. Comment syntax, as for [`sign`](#signtext-options).              |

**Returns** `string`: the start marker, body and end marker lines, without a trailing line break.

**Throws** `GeneratedSignatureSectionIdError` for an invalid id. `GeneratedSignatureCommentStyleError` for an unknown file type.

---

### `mergeSections(params)`

Carries manual sections from an existing file into freshly generated text, matched by id.

| Property    | Type     | Description                                                  |
| ----------- | -------- | ------------------------------------------------------------ |
| `generated` | `string` | Required. New generator output, with default section bodies. |
| `existing`  | `string` | Required. Current file content.                              |

**Returns** `{ text: string, orphans: readonly string[] }`. `text` is `generated` with each section's body taken from `existing` when it has the same id. `orphans` lists ids that only `existing` has and whose body isn't blank. Dropping them would lose someone's edits, so callers should usually fail on them.

**Throws** `GeneratedSignatureMalformedError` if either text's sections are malformed.

---

### `parseSections(text)`

**Returns** `ReadonlyMap<string, ManualSection>` in file order, where `ManualSection` is `{ id, body, startLine, endLine }`. `body` is everything between the marker lines, including its final line break. Lines are 1-indexed.

**Throws** `GeneratedSignatureMalformedError` if markers are unbalanced, nested, duplicated or have an invalid id.

---

### `commentStyle(filePath)`

**Returns** the line comment syntax for a file, as `CommentStyle` (`{ start: string, end?: string }`), looked up by extension or file name (`Dockerfile`, `.gitignore`, …). `null` if unknown, or for formats without comments like `.json`. For any other file, pass `comment` instead of `filePath`.

| `CommentStyle` | Files                                                                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `//`           | `.c`, `.cc`, `.cjs`, `.cpp`, `.cs`, `.cts`, `.go`, `.h`, `.hpp`, `.java`, `.js`, `.json5`, `.jsonc`, `.jsx`, `.kt`, `.less`, `.mjs`, `.mts`, `.rs`, `.scss`, `.swift`, `.ts`, `.tsx`                    |
| `#`            | `.bash`, `.cfg`, `.conf`, `.env`, `.ini`, `.pl`, `.properties`, `.py`, `.r`, `.rb`, `.sh`, `.toml`, `.yaml`, `.yml`, `.zsh`, and `.gitattributes`, `.gitignore`, `.npmignore`, `Dockerfile`, `Makefile` |
| `/* */`        | `.css`                                                                                                                                                                                                  |
| `<!-- -->`     | `.htm`, `.html`, `.md`, `.mdx`, `.svg`, `.vue`, `.xml`                                                                                                                                                  |
| `--`           | `.hs`, `.lua`, `.sql`                                                                                                                                                                                   |

### Manifest

A manifest is a JSON file recording generated files that don't carry their own token, such as JSON files. [`populate-files`](https://www.npmjs.com/package/populate-files) writes it, and these helpers read and check it.

```json
{
  "version": 1,
  "files": {
    "schema.json": { "hash": "v1:…" },
    "types.ts": { "signature": "inline", "inputs": { "generator": "genever@1.4.0" } }
  }
}
```

- Paths are relative to the manifest's directory, with `/` separators.
- `hash` is the [`contentHash`](#contenthashcontent) of the file. `signature: "inline"` means the file carries its own token, which is checked instead.
- `inputs` is optional, and holds hashes of what produced the file, written and checked by the generator. This package doesn't interpret it.

| Function                                                                            | Description                                                                                                                                                                 |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <a id="contenthashcontent"></a>`contentHash(content: string \| Uint8Array): string` | `v1:` and 32 hex characters of SHA-256. `\r\n` counts as `\n`, also in bytes. Manual sections are **not** excluded, so a file with manual sections should be signed inline. |
| `verifyManifestEntry(content: string \| Uint8Array, entry): VerifyResult`           | `valid` or `invalid` for a `hash` entry; [`verify()`](#verifytext)'s result for an `inline` entry.                                                                          |
| `parseManifest(text): Manifest`                                                     | Parses and validates. Throws `GeneratedSignatureManifestError` if the text is not a valid manifest.                                                                         |
| `serializeManifest(files): string`                                                  | Manifest text, with paths and inputs sorted so the output doesn't depend on write order.                                                                                    |

---

### Errors

All errors extend the abstract `GeneratedSignatureError`.

| Error                                 | Properties                                | Thrown when                                                                                                                                                                                                                         |
| ------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GeneratedSignatureMalformedError`    | `reason: MalformedReason`, `line: number` | A token or manual section can't be interpreted. `reason` is one of `'duplicate-section'`, `'duplicate-signature'`, `'invalid-section-id'`, `'nested-section'`, `'unclosed-section'`, `'unopened-section'`, `'unsupported-version'`. |
| `GeneratedSignatureCommentStyleError` | `filePath: string`                        | No comment syntax is known for a file.                                                                                                                                                                                              |
| `GeneratedSignatureSectionIdError`    | `id: string`                              | `manualSection()` gets an invalid id.                                                                                                                                                                                               |
| `GeneratedSignatureManifestError`     |                                           | `parseManifest()` gets text that is not a valid manifest.                                                                                                                                                                           |

## ESLint rules

The plugin is a separate entry point, so importing `generated-signature` never loads it, and `eslint` is only needed when you use it:

```js
// eslint.config.js
import generatedSignature from 'generated-signature/eslint';

export default [generatedSignature.configs.recommended];
```

`configs.recommended` registers the plugin (namespace `generated-signature`) and turns on every rule below as an error. `eslint` is an optional peer dependency (`^10.13.0`), needed only for this entry point. To choose rules yourself, register the plugin: `{ plugins: { 'generated-signature': generatedSignature }, rules: { 'generated-signature/valid': 'warn' } }`.

### `generated-signature/valid`

Reports a file whose signature doesn't match (it was edited outside its manual sections; reported on the token), or whose token or manual sections are malformed (`Generated file is malformed: <reason>`, reported on the line at fault). Unsigned files are ignored. There is no autofix, since re-signing would just approve the edit. Regenerate the file instead, or move the change into a manual section.

```ts
// @generated-signature v1:… Generated file. Do not edit outside of manual sections.
export const generated = 2; // ❌ edited by hand
// @manual-start custom
export const custom = 2; // ✅ manual sections may be edited
// @manual-end custom
```

ESLint only lints the files it is configured for. To check every signed file whatever its type, call [`verify()`](#verifytext) on it.
